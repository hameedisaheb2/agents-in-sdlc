`quality-checks` スキルで自動チェックを実行し、Playwright MCP でブラウザーからフィルターの動作を確認しました。ここでは、明確な QA プロセスを定義したカスタム エージェントに、それらの機能をまとめます。

このレッスンでは、次の操作を行います。

- カスタム エージェントが指示、スキル、MCP ツールと連携する方法を確認します。
- 再利用可能な品質保証プロファイルを作成して確認します。
- QA エージェントを選択し、フィルターの issue に照らして結果をレビューします。

## シナリオ

Tailspin Toys では、プルリクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テスト カバレッジ、ブラウザーでの動作を一貫してレビューしたいと考えています。カスタム エージェントを使うと、QA プロセスを調整し、再利用可能なレポートを作成できます。

## カスタム エージェントとは

カスタム エージェントは、Markdown プロファイルで定義する Copilot の専門版です。プロファイルにはエージェントの目的、指示、利用可能なツールを記述します。このワークショップでは、`.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまでに使ったカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を説明します。`quality-checks` スキルは、繰り返し実行できるチェックをまとめます。Playwright MCP はブラウザー ツールを提供します。QA プロファイルは、これらの機能で要件を評価し、結果を報告する方法を Copilot に伝えます。ほかの機能を置き換えるものではなく、別の会話も必要ありません。

## QA プロファイルを作成する

機能の PR を作成する前に、Copilot に再利用可能な QA プロファイルを作成させます。プロファイルでは、QA が行うチェックと守るべき境界を定義します。

1. Codespace に戻り、フィルターの会話が Interactive モードであることを確認します。
2. 既定のエージェントに、新しいカスタム エージェントの作成を依頼します。

   ```plaintext
   `.github/agents/qa.agent.md` に QA という名前のカスタム エージェントを作成してください。issue と合意済みの要件に照らして機能を確認し、リポジトリの指示に従い、`quality-checks` スキルを実行し、Playwright MCP で動作を検証し、カバレッジが不足している場合はテストを追加してください。

   各要件について、根拠を示して `pass`、`fail`、`blocked` のいずれかを報告させてください。実装コードを変更する前に確認を求め、変更をコミットしたりプルリクエストを作成したりしてはいけません。

   まずはレビューできるように、プロファイルだけを作成してください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、意図した QA の流れと制約がプロファイルに反映されていることを確認します。これにより、検証だけを求めたのにエージェントが機能を変更する事態を防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. フロントマターを確認します。`description` は必須です。`name` は任意ですが、指定するとエージェントの表示名が明確になります。
3. プロファイルの指示を読み、QA が要件を出発点にし、リポジトリの指示に従い、`quality-checks` スキルを実行して Playwright MCP を使うことを確認します。
4. QA が根拠を示し、実装コードを変更する前に確認を求め、変更をコミットしたり PR を作成したりしないことを確認します。
5. これらの役割や制約が不足している場合は、続行する前に既定のエージェントにプロファイルの修正を依頼します。

## issue に対して QA を実行する

Copilot CLI は会話の開始時にプロジェクトのエージェントを読み込みます。プロファイルの作成後に同じフィルターの会話を再開し、QA を選択すると、コンテキスト内の issue と計画時の決定を利用できます。

1. 次のプロンプトを使ってエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> 作成したばかりのエージェントは、利用可能なエージェントの一覧にまだ表示されない場合があります。エージェントは作成されているため、上記のコマンドで有効にできます。

2. 次のプロンプトで QA エージェントに機能をレビューさせます。

   ```plaintext
   issue と計画で決めた内容に照らしてフィルター機能をレビューしてください。PR を作成できる状態ですか？
   ```

3. QA エージェントの作業を確認します。
4. 完了したら、提示されたレポートを読みます。
